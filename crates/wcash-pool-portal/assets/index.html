DOCUMENTATION

How ZecWec works

Full merged-mining guide ↗
01

One search, two targets

The pool builds an ordinary Zcash Equihash job carrying a Wcash commitment. Every share is checked independently against both network targets. Mining Wcash does not reduce Zcash hashrate or block odds.

02

PPLNS accounting

Accepted work enters the rolling PPLNS window. When the pool finds a block, that chain’s reward is allocated from the work selected by its policy. ZEC and WEC balances mature independently.

03

Zero pool fee

The service fee is 0% for both assets. A bounded network transaction fee can be deducted from a payout; unused fee reserve is returned to the miner balance.

04

Shielded WEC payouts

Wcash coinbase funds mature before settlement. Automatic WEC payouts use Ironwood shielded transactions after the account threshold is reached. The public feed shows the transaction ID without exposing recipients or amounts.

05

ZEC settlement

Zcash rewards are tracked independently with the configured ZEC destination. ZEC automatic signing is currently paused; earned ZEC remains recorded for manual settlement when a Zcash block is found.

06

Account safety

The pool never asks for seed phrases or private keys. Portal credentials protect payout settings. ASICs use the public worker name and the ignored password x.

Address compatibility

Shielded Ironwood is recommended. If enabled by the pool, transparent P2PKH payouts expose the destination and transferred amount. Mainnet transparent addresses use W1. W3, TEX, Zcash and wrong-network addresses are not supported.
